# RefScope v0.0.2 — Object Timeline Engine

## Purpose

Convert a flat event stream into a correct per-object lifetime model.

This is the first version where the tool understands that events belong to **instances of objects**, not just pointer values.

## Main problem

A kernel pointer may be reused after free.

Therefore:

```text
ffff888012340000 at t1
```

and the same address at `t2` may refer to different object lifetimes.

RefScope must model:

```text
(object address, generation)
```

not only address.

## Required command

```bash
sudo refscope timeline \
  --target targets/foo.yaml \
  --duration 10s
```

Filter:

```bash
--object 0xffff...
--generation N
```

## Lifetime model

State machine:

```text
UNKNOWN
  ↓ CREATE/first-observed-GET
LIVE
  ↓ FREE/final release
DEAD
```

Events after DEAD are not silently merged into the same generation.

Address reuse creates a new generation.

## Required per-object state

```text
object address
generation
first_seen
last_seen
create event (optional)
free event (optional)
observed get count
observed put count
observed refcount values if available
active semantic reasons
event list
stack fingerprints
tasks/CPUs seen
```

## Refcount handling

RefScope must distinguish:

1. **observed operation balance**
   `observed_gets - observed_puts`

2. **actual kernel refcount value**
   only when explicitly captured/available.

Do not pretend they are equivalent.

Output example:

```text
Observed balance: +1
Kernel refcount: unavailable
```

or:

```text
Observed balance: +1
Kernel refcount after final event: 1
```

## Generation/address reuse

At least one of these must be supported:

- explicit CREATE/FREE;
- allocator/free tracepoint integration for a configured object cache;
- conservative heuristic when create/free unavailable.

If generation is heuristic, mark it as such.

## Timeline output

Text:

```text
Object struct foo @ffff... generation=3

+0.000000 CREATE stack=...
+0.000013 GET reason=WORK ref=2
+0.000081 GET reason=TIMER ref=3
+0.000920 PUT reason=TIMER ref=2
+0.001410 PUT reason=WORK ref=1

END STATE:
  observed balance: 0
  actual refcount: 1
  free observed: no
```

JSON must include identical semantics.

## Suspicion flags

Allowed in v0.0.2:

- `UNBALANCED_OBSERVED_OPS`
- `PUT_WITHOUT_PRIOR_GET`
- `EVENT_AFTER_FREE`
- `ADDRESS_REUSE_AMBIGUOUS`
- `REFCOUNT_NONZERO_AT_END` if actual value known.

These are **not root-cause diagnoses**.

## Stack normalization

To compare stacks later, compute stable fingerprints based on:

```text
symbol name + relative offset/source line
```

Avoid raw ASLR-dependent addresses as the primary identity.

## Data persistence

Add run bundles:

```text
run/
├── meta.json
├── events.jsonl
├── stacks.json
└── summary.json
```

Metadata:
- kernel release;
- build ID if available;
- vmlinux build ID/path;
- RefScope version;
- target spec hash;
- architecture;
- command line;
- capture capability information.

This becomes the input format for v0.1 differential analysis.

## Tests

### Deterministic correct lifetime
Expected:
- 1 generation;
- no suspicion flags.

### Missing PUT
Expected:
- observed balance +1.

### Double PUT
Expected:
- PUT without prior compatible GET / negative balance.

### Address reuse
Create/free object A, allocate object B at same address.

Expected:
- two generations.

### Missing CREATE/FREE
Start tracing after object exists.

Expected:
- `origin=partial`;
- no false claim that first GET created the object.

### Multithreaded operations
GET and PUT from different tasks/CPUs.

Expected:
- same object timeline;
- no assumption that ownership is thread-local.

## Acceptance criteria

- [x] pointer reuse does not merge clearly separate lifetimes;
- [x] timeline survives events from multiple CPUs/tasks;
- [x] actual refcount and observed event balance are separate concepts;
- [x] stack IDs are normalized and persisted;
- [x] run bundle is reproducible and versioned;
- [x] all five tests above pass repeatedly;
- [x] a timeline can be rendered offline from saved data.

## Out of scope

- pairing a specific GET to a specific PUT;
- automatic "missing put is at line X";
- statistical comparison of runs;
- source-level control-flow inference.

## Demo target

Use RxRPC only as a **validation target** if convenient because it already has rich semantic get/put reasons in its own tracing paths.

The goal is to check whether RefScope reconstructs the same high-level lifetime, not to claim RxRPC tracing as novel.

## Go/no-go gate

Proceed only if an object timeline is trustworthy enough that a human looking at it would not immediately prefer raw ftrace/retsnoop output.


## Progress — 2026-10-08

The current implementation and evidence satisfy the acceptance criteria for the
offline v0.0.2 milestone. Evidence is based on the current binary/source hashes
and 12 scenarios repeated 10 times each (120/120 PASS) in
local validation evidence (not included in this repository).

The result is intentionally limited to offline timeline reconstruction. It does
not add root-cause diagnosis, operation pairing, statistical comparison, or
source-level control-flow inference.

## Final v0.2 provenance/discovery matrix — 2026-10-08

The final offline matrix passed the evidence model, inspector/source analysis,
editable YAML adapter, native/ref_tracker/BTF adapter tests, pairing and ambiguity
handling, async transfer annotations, source/BTF manual mode, and v0.0.1/v0.0.2/v0.1
regression tests (`make test`, exit 0). Three structurally different target styles
were synthetic fixtures: acquire precision/recall 3/3, release precision/recall
3/3, false high-confidence candidates 0, false `EXACT` 0. Native tracepoint format
access on the host is denied and remains production-unverified; the adapter degrades
to manual mode.

Discovery is offline and does not auto-attach candidates. Only operations explicitly
selected in target YAML are translated to capture options; the capture CLI caps this
at 32 target functions. Transfer annotations are
offline evidence, not proof of ownership. The final evidence table and hashes are in
local validation evidence (not included in this repository).

This v0.2 result does not close the separate v0.1 real-world RxRPC known-case gate;
that validation remains unverified and synthetic results do not substitute for it.
