# RefScope v0.0.1 — Trace Core

## Purpose

Prove that RefScope can reliably capture manually-described kernel reference events without kernel source modifications.

This release has **zero automatic diagnosis**.

If this layer is unreliable, everything later is invalid.

## User story

Given known wrapper functions such as:

```text
foo_get(struct foo *obj, ...)
foo_put(struct foo *obj, ...)
```

the user can tell RefScope which argument is the object and receive a structured stream of events containing:

- monotonic timestamp;
- CPU;
- PID/TID;
- command name;
- object pointer;
- event type;
- function;
- optional semantic reason argument;
- optional return value;
- kernel stack identifier.

## Required CLI

Minimum:

```bash
sudo refscope trace \
  --get 'foo_get:obj=arg0' \
  --put 'foo_put:obj=arg0' \
  --duration 10s
```

Optional reason:

```bash
--get 'foo_get:obj=arg0,reason=arg1'
```

Filters:

```bash
--pid <PID>
--tid <TID>
--comm <name>
--object <0xffff...>
--cpu <list>
```

Output modes:

```bash
--format text
--format jsonl
```

## Architecture

### Capture backend
Use libbpf CO-RE.

Preferred attach order:

1. fentry/fexit where available;
2. kprobe/kretprobe fallback;
3. existing tracepoint adapter when a subsystem exposes a better semantic event.

Do not attempt to instrument every low-level inline `refcount_*()` operation in this version.

### Event transport
Use BPF ring buffer.

### Event schema

```c
enum refscope_event_type {
    RS_GET,
    RS_PUT,
    RS_CREATE,
    RS_FREE,
    RS_CALL_RETURN
};

struct refscope_event {
    __u64 ts_ns;
    __u64 obj;
    __u64 ip;
    __u64 aux;
    __u32 pid;
    __u32 tid;
    __u32 cpu;
    __u32 stack_id;
    __s32 value;
    __u16 target_id;
    __u8  type;
    __u8  flags;
};
```

Exact field layout may change before v1.0, but events must be versioned from day one.

## Target description

Do not hard-code target logic throughout the program.

Implement a minimal internal target model:

```yaml
name: foo
operations:
  - function: foo_get
    type: get
    object: arg0
    reason: arg1
  - function: foo_put
    type: put
    object: arg0
    reason: arg1
```

YAML parsing may remain experimental, but the architecture must assume data-driven targets.

## Symbolization

Required:
- kernel symbol resolution for function/IP;
- source file:line when matching `vmlinux` DWARF is available;
- graceful fallback to symbol+offset.

Do not build a full debugger.

## Stack capture

Required:
- configurable on/off;
- kernel stack via BPF stack map;
- deduplicate stack traces by stack ID/hash.

Default stack depth: 16 or another measured practical value.

## Reliability requirements

### Event ordering
Preserve per-CPU timestamp ordering.

Global output may be merged by `ts_ns`.

### Loss accounting
Count ring-buffer reservation failures/dropped events.

Final summary must include:

```text
events captured: N
events dropped: M
drop rate: X%
```

Never silently lose events.

### Capability detection
At startup report:
- BTF available?
- fentry available?
- kprobe fallback available?
- stack map available?
- target functions traceable?

`--dry-run` must resolve targets without attaching.

## Tests

### Synthetic kernel module/test target
Create a tiny test module or in-tree-style local test target with:

- one object;
- `test_get()`;
- `test_put()`;
- deterministic reference sequence;
- optional reason enum.

Test sequence:

```text
CREATE
GET reason=A
GET reason=B
PUT reason=B
PUT reason=A
FREE
```

Expected event stream must exactly match.

### Stress test
At least 1,000,000 synthetic get/put operations.

Measure:
- missing events;
- duplicate events;
- reorder errors;
- CPU overhead.

### Architecture
Initial development architecture can be one machine, but code must not contain x86-only assumptions.

If your primary environment is AArch64, v0.0.1 must work there.

## Acceptance criteria

v0.0.1 is complete only when:

- [ ] `--dry-run` validates probes and object/reason argument locations.
- [ ] manual GET/PUT wrappers can be traced.
- [ ] object pointer and timestamp are correct.
- [ ] stacks resolve to symbols.
- [ ] JSONL output is machine-readable.
- [ ] dropped events are explicitly counted.
- [ ] synthetic deterministic test passes 100 consecutive runs.
- [ ] million-event stress test has a documented drop rate.
- [ ] process exits cleanly and detaches all probes.
- [ ] invalid target specs fail with a precise error.

## Explicitly out of scope

Do not implement:
- automatic get/put discovery;
- ownership pairing;
- AI;
- good/bad comparison;
- graph visualization;
- syzbot automation;
- TUI;
- web UI;
- automatic patch generation.

## Benchmark to record

Baseline synthetic test runtime vs tracing runtime.

Report:
- events/sec;
- CPU overhead;
- memory usage;
- drop rate.

This is a debugging tool, so production-grade <1% overhead is not required. Reliability matters more.

## Release artifact

README demo should be no longer than:

```text
$ refscope trace ...
GET ...
GET ...
PUT ...
PUT ...
```

Do not market this release as innovative. It is infrastructure for the real project.

## Go/no-go gate

Proceed only if capture is reliable enough that later diagnostic mistakes cannot be blamed on lost/misidentified events.
